## 1. 기존 문서에서 빠진 대화 내용

저장소 문서를 만들 때 대화 일부가 빠졌다. 계획에 다시 넣는다.

### 1-1. 달고나 뽑기가 이 게임의 차별점
대화 12장 "최종 개발 방향"의 결론은 **"우리 게임만의 차별점은 달고나 뽑기"**이다. 달고나를 만들어 파는 데서 끝내지 않고, 바늘로 모양을 얼마나 완벽하게 떼어 냈는지로 결과가 갈려야 한다.
그런데 저장소의 MVP 체크리스트에는 4단계(가열·혼합·압착·도장)만 있고 뽑기가 빠졌다.
대화에서 정한 규칙은 아래와 같다.
- 뽑기는 **선택형 도전**이다. 성공하면 보너스를 받고, 실패해도 기본 판매는 할 수 있다.
- 다른 플레이어와 하는 **"달고나 뽑기 대결"**(정해진 시간 안에 모양을 얼마나 완벽하게 떼어 내는지)은 별도 콘텐츠 후보이다.

→ **권장:** 뽑기는 5단계(선택)로 MVP에 넣는다. 대결은 보류한다.

### 1-2. 원칙: "숫자만 바뀌는 미니게임 금지"
실제 달고나 오브젝트의 색, 크기, 두께, 모양이 조작 결과에 따라 눈앞에서 바뀌어야 손맛이 산다. (대화 12장)

### 1-3. 품질 평가 항목
설탕의 색·탄 정도, 두께가 고른지, 모양의 위치와 선명도, 완성품이 깨졌는지.

### 1-4. 주문 예시 (보류 기능의 재료)
별 2개 / 하트 3개 / 완성도 80% 이상 1개 / 안 깨진 달고나 5개 / 황금색 1개 / VIP 고난도 주문.
손님 유형은 동네 아이(쉬운 주문), 단골(특정 조건, 보상 높음), 관광객(희귀 도안), VIP(고난도)로 나눈다.

### 1-5. 레벨업 코인 보상 (대화 안)
Lv2 100, Lv3 50(+도안), Lv4 150, Lv5 200, Lv6 250, Lv7 300, Lv8~10 200~350, Lv11~14 500, Lv15 700, Lv16~20 1,000. 기존 문서에는 EXP 요구량만 남아 있다.

### 1-6. 알바생 확장 아이디어 (보류)
- 성격 특성: 빠른 손(속도), 꼼꼼함(불량 감소), 절약 정신(재료 감소), 친절함(손님 만족), 장인 정신(품질).
- **채용 게시판**: 후보가 무작위로 나오고, 마음에 드는 직원을 기다렸다가 고용한다. 대화에서 가장 추천한 확장 기능이다.
- 직원 꾸미기(앞치마·모자), 직원 교육(코인으로 EXP), 이벤트 특별 직원.
- 직원이 만든 달고나와 플레이어가 직접 만든 달고나를 따로 기록한다(직접 제작 랭킹과 자동 생산 랭킹 분리).

### 1-7. 월드 후보 (보류)
개인 가게 / 중앙 광장 / 재료 상점 / 도안 교환소 / 달고나 대회장 / 랭킹 게시판 / 이벤트 공간. 멀티 기능은 친구 가게 방문, 좋아요, 구경.

### 1-8. 수익화 방향 (보류)
VIP 패스, 추가 작업대, 특별 화로 외형, 포장지 컬렉션, 가게 스킨(포장마차 → 모던), 이모트(먹기·자랑하기).
**제작 미니게임을 돈으로 건너뛰게 하는 상품은 만들지 않는다**(핵심 재미가 사라진다).

## 4. 제작 미니게임 상세 (가장 중요) — v2, 2026-11-17

v1에서 바뀐 점: 실제 달고나 만드는 영상(YouTube Shorts 1AbXU2OsGhA)의 순서와, 사용자가 승인한 조작 변경 4개(설탕 넣기 추가 / 젓기 + 속도 게이지 / 국자를 끌어 기울여 붓기 / 영상 1식 화면 배치)를 반영했다. 근거는 `docs/MOTION_REFERENCE_ANALYSIS.md`.

한 번 만드는 데 **35~45초**(뽑기 제외). 작업대 앞에서 E(폰은 버튼) → 카메라가 작업대를 비스듬히 내려다봄.
화면 가운데에는 **실제 3D 국자, 나무젓가락, 철판, 달고나**가 보이고, 손가락을 대는 즉시(1프레임 안) 물체가 반응한다. 손을 떼면 0.1~0.2초 스프링으로 돌아온다.

### 4-1. 화면 배치 (영상 1식)
- **위 가운데:** 단계 칩 `✓설탕 — 녹이기 — 소다 — 붓기 — 누르기 — 모양`. 지금 단계는 검은 칩, 끝난 단계는 ✓.
- **왼쪽:** "다음 단계" 카드(그림 + 한 줄 설명).
- **오른쪽:** QUALITY 원형 게이지(완성도 %) + 별 3개 + "고르게 녹일수록 황금 달고나 확률↑".
- **아래 가운데:** 지시문(검은 알약) + 작은 부제. 실수하면 부제가 빨간 힌트로 바뀐다(예: "불에서 조금 떨어뜨려요").
- **왼쪽 아래 ✕**, **오른쪽 위 진동 켜기/끄기**(폰 햅틱).
- 단계 안에서는 카메라 고정. 단계가 바뀔 때만 컷 1프레임 + 0.2~0.3초 ease-out으로 옮긴다.

### 4-2. 단계 (실제 순서 그대로)

| 단계 | 실제 영상 | 화면에 보이는 것 | 조작 (PC 마우스 = 폰 손가락) | 점수 | 실패 |
|---|---|---|---|---|---|
| 0. 준비 (자동) | 검은 철판에 설탕을 둥글게 깔아 둠 | 철판 위 하얀 설탕 원(붓기 목표) | 없음. 0.5초 연출 | — | — |
| 1. 설탕 넣기 (T의 일부) | 백설탕 2스푼 + 황설탕 1/4스푼을 구리 국자에 | 설탕 그릇 2개(흰 / 노란), 나무 숟가락 | 숟가락을 그릇에서 국자 위로 **끌면 기울어지며 쏟아짐**(40° 넘으면 알갱이). 백설탕 2번, 황설탕 1번 | 정량에 가까울수록 높음(국자 위에 쏟은 양만 셈) | 국자 밖에 흘리면 철판에 알갱이가 남음(감점만) |
| 2. 녹이기 (T) | 중불, 국자를 **불에서 조금 띄워** 나무젓가락으로 계속 저음. 흰 설탕 → 투명한 호박색 액체 + 남은 알갱이 → 완전히 투명 | 국자 속 설탕, 아래 불꽃(연탄불). `STIR SPEED` 게이지(SLOW / JUST RIGHT / FAST)와 온도 색 | 국자 안에서 **원을 그리며 드래그** = 나무젓가락이 따라 저음. **원을 그리는 높이 = 국자 높이**: 손가락을 화면 위쪽으로 올려 저으면 국자가 불에서 떨어져 덜 뜨거워짐 | 젓기 속도가 초록에 있던 비율 + 온도가 적정이던 비율. 알갱이가 다 녹으면 단계 끝 | 너무 가까이 / 오래 → 갈색 → 검게 탐(**Burnt**, 그 자리에서 끝). 너무 느리면 바닥이 눌어붙음(감점) |
| 3. 소다 (M) | 다 녹은 순간 나무젓가락 끝에 소다를 묻혀 국자에 2~3번 톡 → 불에서 떼고 빠르게 저으면 3.5초 동안 불투명한 연갈색으로 부풀어 오름 (MOTION_REFERENCE 7·8장) | 소다 통, 젓가락 끝 흰 가루, 액체 위 흰 소다 점, 부푸는 거품 | ① 소다 통 → 국자로 끌기 = 한 번 찍기(**횟수 = 양**: 1번 적음 / 2~3번 알맞음 / 4번 이상 많음) ② 국자를 눌러 **빠르게 젓기**(FAST가 정답, 불 가까이 저으면 빨리 탐) | 소다 넣은 타이밍(투명해진 직후가 최고) + 양 + 부푼 정도 | 소다 너무 많음 → 진한 갈색에 쓴맛(감점, 색 어두워짐). 너무 늦게 넣음 → 이미 탐. 덜 저음 → 덜 부풂. 불 위에서 저음 → 탐 |
| 4. 붓기 (P의 일부) | 국자를 거의 90°로 뒤집어 설탕 원 가운데에 걸쭉한 반죽을 덩어리째 쏟고, 젓가락으로 긁어냄 | 철판 위 설탕 원, 국자 | 국자를 **끌어 철판 위로 가져가 기울이기**. 액체 줄기가 아니라 **걸쭉한 덩어리가 미끄러져 떨어짐**. 끝에 국자를 톡 털면(탭) 남은 반죽이 떨어짐 | 떨어진 덩어리 중심이 설탕 원 가운데에 가까울수록 + 국자에 남은 양이 적을수록 | 원 밖에 떨어지면 철판에 들러붙어 모양이 찌그러짐 |
| 5. 누르기 (P) | "확! 누르지 말고 3번 정도 나눠서" 둥근 누름판으로 누름. 덩어리 → 두꺼운 원판 → 넓고 얇은 원판 | 누름판(위에 세운 손잡이), 아래 반죽 | **꾹 누르고 있으면 내려가고, 떼면 올라감.** 3번 나눠 누르기. 매번 원판이 넓어지고 얇아짐 | 3번 모두 목표 두께 구간에 멈췄는지 + 원이 고르게 퍼졌는지 | 한 번에 너무 세게 / 오래 → 가장자리가 갈라짐, 너무 얇아짐(뽑기 난이도↑). 너무 약하게 → 두꺼워 각인이 흐림 |
| 6. 모양 (S) | 별 틀을 원판 위에 올리고 누름판으로 "살살" 눌러 각인. 틀을 들면 별 모양 자국 | 고른 도안의 철사 틀, 누름판 | ① 틀을 **끌어서 원판 가운데에 놓기** ② 누름판을 **살살 짧게** 누르기 | 중심 거리 + 각도 + 누른 세기(적당) | 세게 누르면 틀이 끝까지 박혀 금이 감(깨짐 위험, 감점) |
| 7. 뽑기 (선택) | — (게임 오리지널) | 바늘, 점선 각인선, 금 간 곳이 빨갛게 | 바늘을 **선 따라 드래그**. 빠르게 긋거나 벗어나면 금이 커짐. 언제든 "그만하고 팔기" | 따라간 비율과 금 개수 | 금이 한도를 넘으면 쪼개짐 → Poor로 팔림 |

판정 공식은 v1 그대로 Q = 0.25T + 0.20M + 0.25P + 0.30S. T = 설탕 넣기 20% + 녹이기 80%, P = 붓기 30% + 누르기 70%.

**단계별 목표 시간:** 설탕 넣기 5초 / 녹이기 10~12초 / 소다 5~6초 / 붓기 4초 / 누르기 6초 / 모양 4초 / 뽑기 10~20초(선택).

### 4-3. 보이는 변화 (숫자가 아니라 물체로)
| 단계 | 물체 변화 |
|---|---|
| 녹이기 | 흰 알갱이 → 가장자리부터 투명한 호박색 액체가 번지고 알갱이가 줄어듦 → 완전 투명. 오래 끌면 진갈색 → 검정 + 연기 |
| 소다 | 하얀 무더기가 닿은 곳부터 불투명한 연갈색으로 번지며 0.5초 만에 부피가 1.5배로 부풀어 오름. 저을수록 크림처럼 매끈해짐 |
| 붓기 | 걸쭉한 덩어리가 국자 가장자리를 타고 늘어지며 떨어지고, 철판 위에서 울퉁불퉁한 언덕 모양으로 쌓임 |
| 누르기 | 언덕 → 두꺼운 원 → 넓고 얇은 원. 매번 누르는 동안 지름이 커지고, 떼면 살짝 되돌아옴 |
| 모양 | 틀 아래로 선이 파이고, 틀을 들면 자국이 남음 |

**결과 화면:** 등급 도장(Burnt~Perfect), 별 3개가 0.2초 간격으로 채워짐, 판매 예정가("한 개 OO코인부터 · Perfect면 OO코인"), 뽑기 성공 시 "완벽 뽑기!" 배지, 도감에 새로 들어간 것. 버튼: **다시 하기**(주 버튼) / 다른 도안 / 나가기.

**결과물 외형** (모델 1개 + 속성으로 표현)

| 속성 | 바뀌는 것 |
|---|---|
| 색 | 녹이기·소다 결과: 연한 황금 → 황금 → 진갈색 → 검정 |
| 지름·두께 | 누르기 결과 |
| 각인 | 모양 결과: 선명도와 위치 |
| 깨짐 | 누르기 갈라짐 + 뽑기 결과 |
| Perfect | 반짝임 파티클 |

**서버 검증:** 클라이언트는 입력 기록만 보낸다(단계마다 누른 시각, 뗀 시각, 드래그 표본 최대 60개). 서버는 세션 ID, 단계 순서, 최소 시간(단계당 1.5초 이상)과 최대 시간을 확인한 뒤 같은 공식으로 다시 계산한다. 클라이언트가 보여 준 점수와 서버 점수가 다르면 서버 점수를 쓴다.

## 6. 개발 순서

원칙은 대화 10장의 **"먼저 만드는 재미를 검증하고, 그다음 타이쿤을 붙인다"**이다.
대화 끝 13장은 반대로 "가게 배정 + 저장부터"를 추천했다. 하지만 이 게임에서 가장 큰 위험은 미니게임이 재미없을 가능성이다. 그래서 **권장 순서는 제작 프로토타입 → 기반**이다. 저장과 가게 배정은 이미 오후(OHU) 프로젝트에서 검증된 코드 패턴이 있어 위험이 작다.

## 7. 직원 대신 "달고나 기계"를 쓸지 (결정 필요)

레퍼런스 `기계/` 폴더의 금형 달고나 기계와 자판기는 한국 골목 테마에 잘 맞는 **자동 생산 설비**이다. 선택지는 두 가지이다.
- **A (대화 원안):** 알바생 직원. 등급·급여·고용비. 수집 재미가 있지만 NPC 직원 모델과 애니메이션 작업량이 크다.
- **B:** 달고나 기계 설비. 사서 놓으면 기본 도안을 금형으로 찍어 냄. 급여 대신 연료(연탄)를 쓰고, 기계 등급이 직원 등급을 대신한다. 구현이 가볍고 레퍼런스와 맞는다.

**권장:** MVP(Phase 5)는 **B로 가볍게** 만들고, A는 채용 게시판과 함께 출시 이후 확장으로 넘긴다. 사용자 결정이 필요하다.

**2026-11-19 갱신:** 사용자 추가 기획(ChatGPT 대화)에서 **둘 다 쓰는 안**이 나왔다. 1단계 연탄 화로에서는 국자를 늘리고 남는 국자에 알바생(A)을 두고(Lv3·5·8), Lv10부터는 시대별 기계(B)로 바꾸고, Lv25에 공장. 자세한 레벨·비용·생산량은 [`SHOP_GROWTH_PLAN.md`](SHOP_GROWTH_PLAN.md). 이 안이 승인되면 `SYSTEMS_SPECIFICATION.md` 5장·`ECONOMY_BALANCE.md` 6장의 직원 안을 고친다.

## 8. 작업 방식 (오후 프로젝트에서 가져온 규칙)

- GitHub가 원본이다. 기능마다 브랜치를 만들고, Studio에서 테스트하고, 푸시한 뒤 사용자가 승인하면 `main`에 머지한다.
- 코드는 Rojo로 동기화한다(Studio에 코드를 붙여 넣지 않음). 맵은 스크립트로 만들고 Studio에서 손으로 끌어 옮기지 않는다.
- 기본 테스트는 **Studio 2인 + 폰 화면 에뮬레이션**이다.
- 서버가 코인·재고·품질을 결정한다. RemoteEvent는 타입, 범위, 호출 빈도를 검사한다.
- Creator Store 에셋은 후보를 먼저 보여 주고 고르게 한다. 들어 있는 스크립트는 모두 지운다.
- 매일 `docs/WORKLOG.md`에 한 일, 스크린샷, 다음 할 일을 남긴다. 결정은 `DECISION_LOG`에 번호(D-001…)를 붙여 기록한다.
- Luau 한 스크립트의 로컬 변수 200개 제한에 걸리지 않게, 미니게임은 단계마다 모듈 하나로 나눈다.
