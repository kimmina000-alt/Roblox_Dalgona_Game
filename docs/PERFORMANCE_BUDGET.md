## 3. 넘치는 곳과 줄일 방안 (기획안)

1. **공장 (약 6만 삼각형)**
   - 남의 공장은 가까이 갔을 때만 3D를 보이고, 멀면 단순한 상자로 둔다 (클라이언트에서 거리로 바꿈).
   - 또는 공장 glb를 Blender에서 반으로 줄인다 (목표 2.5만).
2. **스트리밍 목표 반경 1024 → 256**
   - 부지 6칸 전체 폭이 240이라 256이면 골목 전체가 보이고, 멀리 있는 것(공장 뒤 부지 등)은 덜 받는다.
3. **손님 (명당 4,800~8,100)**
   - 서버 전체로 최대 18명이면 약 12만 삼각형이다.
   - 손님 NPC 세션에 명당 3,000 이하인 가벼운 판을 요청한다.
   - 화면에서 80칸 넘게 떨어진 손님은 팔다리 흔들기를 멈춘다.
4. **손 작업대 (부품 약 445개)**
   - 남의 가게 작업대는 꾸미기(Stage1Decor·PackArea의 작은 소품)를 숨긴다.
   - 또는 움직이지 않는 부품을 메시 하나로 합친다.
5. **가게 알바생 미니미**
   - 액세서리 최대 3개 제한은 이미 들어가 있다. 공장 공정 알바생은 멀면 멈춘 자세로 둔다 (제작 세션이 넣음).

바꾸기 전에 사용자와 PM에게 우선순위를 묻는다. 1·2번이 효과가 가장 크다.

## 4. 성능 개선 1·2 적용 (2026-11-22, feat/perf-1122)

### 적용한 것
- **1. 남의 공장은 멀면 상자로**: 새 클라이언트 스크립트 `FactoryLod`. 남의 공장(`FactoryLot.Building`·`Staff`)이 카메라에서 120칸 밖이면 내 화면에서만 숨기고(LocalTransparencyModifier = 1) 같은 크기·색의 낮은 상자 2개를 보임. 110칸 안으로 오면 원래대로. 수치는 `GrowthConfig.Perf`.
- **2. 스트리밍 반경 1024 → 256** (Studio Workspace 속성, 장소 버전 150에 저장). 맵 안 모든 것이 골목 가운데에서 200칸 안이라 256이면 가게 6칸 전부가 들어옴 → Persistent로 둘 모델은 없음.

### 스트리밍 전·후
- 전(1024): 클라이언트 인스턴스 약 64,000, 메모리 약 1,150~1,180MB (Studio).
- 후(256): 같은 자리·같은 카메라에서 인스턴스 64,040, 화면 삼각형 135,916, 드로콜 138 → **지금 맵에서는 차이 없음** (모든 것이 256 안). 맵이 커지거나 레트로 골목이 붙을 때 효과.
- 보이는지 확인 (256, 4인 테스트): 내 가게 입구에서 진열대·기계·공장 문·작업대·간판·가게 건물·공장 부지 모두 받아짐. 스폰(0,0)에서 다른 가게 간판 6개 모두 보임 (75~123칸).
