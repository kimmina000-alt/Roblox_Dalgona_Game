## 0. 작업 규칙 (2026-11-24 사용자 결정 "응 바꿔", 토큰 절약)

1. 세션은 코드를 자기 브랜치에 커밋·푸시만 한다. 기본으로 Studio를 쓰지 않고 rojo serve를 켜지 않는다.
2. 어느 세션도 main에 직접 머지하지 않는다. 묶음 끝에 PM이 시험 브랜치(`test/batch-<날짜>`)에 모아 합치고 → 저장·부지 세션이 시험 → 달고나 게임 세션에 보고 → 달고나 게임 세션이 main 머지(2026-11-24 사용자 결정).
3. Rojo는 쓰지 않는다(2026-11-24 사용자 결정). 묶음 시험 때 시험 담당(저장·부지 세션)이 MCP로 시험 브랜치와 Studio 체크섬을 비교해 다른 스크립트만 넣고, 다시 체크섬으로 같은지 확인한 뒤 시험. main 머지 뒤 장소 저장은 달고나 게임 세션이 한 번.
4. 예외: 화면을 직접 봐야만 고칠 수 있는 일만 그 세션이 Studio를 쓴다(MCP로 확인 후 되돌림 우선).
5. 보고는 짧게, 진행 소식은 묶음 끝 요약. 사용자 질문은 PM 한 곳에서만.
